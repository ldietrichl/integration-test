# REST mTLS PKCS12 configuration

## Purpose

Integration tests can use the client-auth PKCS12 generated by the OpenShift Service Access Tool.
The certificate file and password are local corporate artifacts and must not be committed to the project.

## Files

| File | Purpose |
| --- | --- |
| `src/test/resources/stand.properties` | Non-secret stand-level mTLS switches and secure placeholders |
| `secure.local.properties` | Versioned template with the `SECURE_MTLS_CLIENT_PKCS12_PASSWORD` placeholder |
| `secure.local.override.properties` | Ignored local file where the real PKCS12 password is set |
| `src/main/java/config/services/rest/RestMtlsConfiguration.java` | Shared RestAssured mTLS configuration |

## DEV setup

1. Run the OpenShift Service Access Tool on the corporate workstation.
2. Keep the generated PKCS12 and ingress truststore outside the project and put their paths only in `secure.local.override.properties`:

```text
SECURE_MTLS_KEYSTORE_PATH=<absolute path to mtls-client-auth.p12>
SECURE_MTLS_TRUSTSTORE_PATH=<absolute path to ingress-v2-truststore.p12>
```

3. Set the DEV PKCS12 password only in `secure.local.override.properties`:

```properties
SECURE_MTLS_CLIENT_PKCS12_PASSWORD=<password assigned when the client PKCS12 was created>
SECURE_MTLS_TRUSTSTORE_PASSWORD=<password assigned when the truststore was created>
```

4. Keep `src/test/resources/stand.properties` enabled for DEV:

```properties
stand.dev.mtls.enabled=true
stand.dev.mtls.client.pkcs12=${SECURE_MTLS_KEYSTORE_PATH}
stand.dev.mtls.client.pkcs12.type=PKCS12
stand.dev.mtls.client.pkcs12.password=${SECURE_MTLS_CLIENT_PKCS12_PASSWORD}
```

## Notes

The REST base URI keys in `test.properties` remain gateway/service roots because endpoint constants append paths.
The generated service diagnostics are split deliberately:

```properties
stand.dev.services.<service>.base-uri=<gateway root without API path>
stand.dev.services.<service>.mtls.probe-path=<diagnostic API path>
stand.dev.services.<service>.mtls.probe-url=<full diagnostic URL>
```

Do not use `stand.dev.services.*.mtls.probe-url` as a RestAssured `baseUri`; it is only a ready-made health/probe URL.

DEV uses strict server and hostname verification. The truststore must contain a valid X.509 CA entry; do not import every file merely carrying a `.pem` suffix.

```properties
stand.dev.mtls.server-tls.relaxed=false
stand.dev.mtls.truststore=${SECURE_MTLS_TRUSTSTORE_PATH}
stand.dev.mtls.truststore.type=PKCS12
stand.dev.mtls.truststore.password=${SECURE_MTLS_TRUSTSTORE_PASSWORD}
```
