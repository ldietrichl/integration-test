# Единый Gradle 8.4 для integration-test

Дата изменения конфигурации: 2026-09-15.

Настройка загрузки из Nexus, общего пользовательского кеша и сборки без тестов:
[Gradle и Nexus](GRADLE_NEXUS.md). Попытка компиляции 2026-09-15 остановилась
на загрузке дистрибутива из-за UnknownHostException; это не успешная сборка.

## Область изменения

Все задачи этого integration-test используют Gradle **8.4** и существующий JDK **17**:
scheduler, splitter, experiment, data-operator, preflight, reporting и остальные задачи.
Это не изменение исходников сервиса scheduler или отдельного репозитория platform-v-at.
Версии зависимостей фреймворка, Allure, JUnit, Groovy и настройки DEV/IFT не обновляются.

Изменено:

- Wrapper выбирает `gradle-8.4-bin.zip` из прежнего корпоративного Nexus.
- Закреплена официальная контрольная сумма дистрибутива.
- `settings.gradle.kts` останавливает конфигурацию при версии Gradle, отличной от 8.4.
- Задача `wrapper` сохраняет версию 8.4, корпоративный URL и SHA-256 при последующей генерации.
- Устаревшие Kotlin-вызовы `toLowerCase/toUpperCase` заменены на `lowercase/uppercase`.
- Локальный runner scheduler использует `gradle:8.4-jdk17` и ту же проверку версии.
- Обновлены действующие инструкции; исторические отчёты прошлых прогонов не переписаны.

Существующие `gradlew`, `gradlew.bat` и `gradle-wrapper.jar` остаются bootstrap-файлами:
версию запускаемой сборки определяет `gradle-wrapper.properties`.
Они включены в корпоративный пакет, но не перегенерировались выполнением Gradle.

## Дистрибутив

```properties
distributionUrl=https\://nexus-ci.delta.sbrf.ru/repository/raw-public-cache/gradle_distr_proxy/gradle-8.4-bin.zip
distributionSha256Sum=3e1af3ae886920c3ac87f7a91f816c0c7c436f276a6eefdb3da152100fef72ae
```

Источник контрольной суммы: [официальные checksums Gradle](https://gradle.org/release-checksums/).
Корпоративный Nexus должен отдавать оригинальный bin-архив 8.4 с этой суммой.
Доступность данного пути в Nexus из ВАРМ при подготовке не проверялась.

Если загрузка возвращает 404, попросите администратора разместить утверждённый
дистрибутив по этому адресу либо используйте уже установленный **Gradle 8.4**.
Не удаляйте checksum и не подменяйте URL другим архивом для обхода ошибки.
Расположение кеша зависит от URL: ранее скачанный через другой адрес архив
может не использоваться wrapper автоматически. Не переименовывайте и не очищайте кеш наугад.

Не требуется менять `test.properties`, kubeconfig, CA, client certificates,
secure.local.override.properties, DB или параметры oc.

## IDEA

1. Откройте Settings → Build, Execution, Deployment → Build Tools → Gradle.
2. Gradle distribution: **Wrapper** / gradle-wrapper.properties.
3. Gradle JVM: установленный **JDK 17**.
4. Перезагрузите Gradle-проект.

Project SDK также оставьте JDK 17. Gradle JVM и JDK для запуска теста могут
настраиваться независимо, поэтому проверьте оба выбора на ВАРМ.
Для запуска пакета из IDEA свойства scheduler/DEV/IFT остаются прежними.

Gradle 8.4 умеет использовать Java 21 toolchain, но не запускаться на Java 21.
В этом проекте переход на Java 21 не выполняется.
Источник: [Gradle 8.4 release notes](https://docs.gradle.org/8.4/release-notes.html).

## Команды на ВАРМ

Из `C:/Work/IdeaProjects/integration-test`:

```powershell
.\gradlew.bat --version
.\gradlew.bat testClasses --console=plain
```

Первая команда должна показывать Gradle 8.4 и JVM 17.
Вторая компилирует исходники, но не запускает бизнес-сценарии.
Команды приведены для следующей проверки, при подготовке миграции они не выполнялись.

После успешной компиляции:

```powershell
.\gradlew.bat schedulerReadOnlyRegression -PschedulerTunnel=true --console=plain
```

Имя задачи: **schedulerReadOnlyRegression**, не `shedulerReadOnlyRegression`.

Остальные задачи и их параметры сохранены. Для полного регресса по-прежнему
нужны корректный стенд, права и разрешения на фикстуры; версия Gradle не снимает
ограничения manual/managed, изоляции и остановки jobs.

При недоступном wrapper-дистрибутиве допустим явно установленный Gradle 8.4:

```powershell
$gradle84 = Read-Host 'Полный путь к установленному Gradle 8.4 bin/gradle.bat'
& $gradle84 --version
& $gradle84 testClasses --console=plain
```

Системный Gradle 7.3.3 или 8.10 больше не является альтернативным режимом проекта.
Автоматического fallback на другую версию нет.
Для Linux/CI используйте `./gradlew` и JDK 17; для Windows CI используйте `.\gradlew.bat`.
Не создавайте дополнительную несогласованную версию Gradle в настройках CI.

## Локальные контейнеры

`local-services/scheduler-regression/compose.contracts.yml` теперь выбирает
`gradle:8.4-jdk17`. Контейнерный build-скрипт отклоняет другую версию.

Изменение YAML не пересоздаёт запущенные контейнеры. Обновление образа, компиляция,
экспорт зависимостей и повторный контейнерный прогон здесь не выполнялись.
Старый runtime-export не следует считать новым результатом сборки на 8.4.
Следуйте FULL-STACK-RUNBOOK.md при отдельном согласованном запуске.

## Что ещё не подтверждено

- Попытка wrapper-загрузки из корпоративного Nexus завершилась UnknownHostException.
- Запуск testClasses не дошёл до конфигурации Gradle и компиляции.
- Тесты, Docker и генерация нового Allure-отчёта не запускались.
- Новая задача compileWithoutTests подготовлена, её выполнение пока не подтверждено.
- Совместимость всех плагинов и исходников с 8.4 требует фактической сборки.
- Миграция Gradle сама по себе не исправляет `cannot find symbol` в Java-коде.
  Последний присланный запуск завершился до тестов, поэтому текущая компиляция
  DictionariesV1Steps и всего проекта остаётся отдельным шагом.
- Исторические результаты на 7.3.3 и прошлые архивы патчей не являются проверкой 8.4.

Для анализа следующей попытки сохраняйте консоль и артефакты одного запуска.
Успешное чтение `--version` не равно успешной компиляции, а компиляция не равна
успешному регрессу или покрытию требований.

## Откат

Восстановите файлы из резервной копии установленного патча.
Не возвращайте только distributionUrl: ограничения версии, настройка задачи
wrapper и контейнерного runner должны оставаться согласованными.
Кеши, БД, контейнерные volumes, секреты и результаты предыдущих прогонов не удаляйте.
