# EXPLAB-2974: локальный прогон и анализ лога, 07.09.2026

Ветка тестов: `feature/EXPLAB-2974-data-operator`. Проверяемый сервис: исходники пользовательского архива `06fd6acb646`. Все 74 Java-файла сверены с ZIP по SHA-256 и не изменены. В локальном POM используются публичный Apache Ignite 2.17.0 вместо SE 17.6.0 и отключены недоступные SE security-модули.

По просьбе пользователя выполнен ещё один [прогон с альтернативными версиями Ignite 2.18.0 и Kafka 3.9.1](COMPATIBLE_VERSIONS_RUN_20260907.md). Результат каждого из 103 вариантов совпал; ниже сохранён разбор исходного окружения.

[Проверка влияния соседних сервисов](FAILURE_CAUSES_AND_DEPENDENCIES_20260907.md): при временном отключении dictionaries/experiments после загрузки справочников все 103 ответа сохранились без изменений, кроме timestamp.

**Результат: 103/103 варианта выполнены, 0 passed, 103 failed, 0 broken, 0 skipped.** Повтор после остановки и запуска окружения дал тот же HTTP-статус и результат для каждого варианта. Это проверка реализованной части SL-35–43 и SL-45, а не всех 50 пунктов endpoint-плана и не подтверждение прежних 83,3%.

Сам data-operator работает: health UP, контрольный корректный POST вернул HTTP 200 с `objectIdType=INTEGER`, `parentIdType=INTEGER` и сохранённым пустым условием. Ignite ACTIVE; Kafka consumer получил partition `explab-2974-cj-config-log-0`. Полные dictionaries/experiments заменены локальными ответами зависимостей. TLS/mTLS, Ignite SE и сквозное взаимодействие с этими сервисами в результат не входят.

## Что показывает лог сервиса

77 ответам 500 соответствуют 77 записей общего обработчика: 63 `HttpMessageNotReadableException`, 4 `MethodArgumentNotValidException` и 10 `RuntimeException`, в которые сервис оборачивает `NullPointerException`. На уровне бизнес-сервиса дополнительно записаны сами 10 NPE и 2 ошибки отсутствующего справочника, поэтому всего в интервале прогона 89 ERROR-записей. Это не 89 независимых запросов с HTTP 500.

| Наблюдение | Причина по коду и логу | Пример |
|---|---|---|
| 63 ошибки чтения JSON дают 500 | `GlobalExceptionHandler.handleGeneric(Exception)` перехватывает ошибки десериализации и возвращает 500. | SL-43, `dataType="UNKNOWN"`: `HttpMessageNotReadableException`, HTTP 500, `message="Внутренняя ошибка сервиса"`. |
| 4 ошибки корневых обязательных полей дают 500 | Bean Validation срабатывает, но `MethodArgumentNotValidException` попадает в тот же общий обработчик. | SL-35: `splittingPointCode` отсутствует/null; аналогично `exps`. |
| Вложенные отсутствующие данные доходят до расчёта | На вложенных объектах и коллекциях нет каскадного `@Valid`. Сервис обращается к null-условиям/rules/оператору и оборачивает NPE в RuntimeException. | 2 NPE на `getObjectsSelectConditions().isEmpty()`, 2 на `getRules().stream()`, 2 на null `operation`, по одному на null exp/cond, ещё 2 на null-вложенной структуре rules. |
| 24 некорректных запроса принимаются | Не обеспечены вложенная обязательность, непустота exps, строгие JSON-типы и диапазон int16. | `exps=[]`, отсутствующие/null expId и number, часть полей правила, число/boolean/null внутри массивов строк. |
| Дробные и слишком большие относительно int16 значения принимаются | `number` в DTO — Integer без ограничения int16; Jackson выполняет преобразование чисел. | SL-42: 32768, -32769 и 1.5 возвращают 200; SL-41: expId=1.5 возвращает 200. |
| Два HTTP 400 имеют неверную причину и схему | Число/boolean в splittingPointCode преобразуются в строку. Поиск метаданных для `123`/`true` вызывает IllegalStateException, затем IllegalArgumentException с текстом 422; handler отправляет HTTP 400 без UUID. | Тело: `{"message":"422 Некорректные данные в БД","error":"Bad Request","status":400,"timestamp":"..."}`. |

Файлы для исправления в исходниках сервиса:

- `errorhandler/GlobalExceptionHandler.java`: раздельная обработка валидации/десериализации и стабильная схема ошибки v7.
- `api/dto/request/SplittingObjectsLinksRequestDto.java`, `ExpConditionDetailDto.java`, `ObjectSelectConditionsDto.java`, `RuleDto.java`: каскадная валидация, непустые коллекции, корректные ограничения типов и диапазон number. `@NotBlank` нельзя применять к List/enum; добавление одного `@Valid` без исправления аннотаций недостаточно.
- Настройка Jackson: запрет нежелательных преобразований чисел/boolean в строки и дробей в целые для этого контракта.
- `service/DataOperatorServiceImpl.java`: отделить ошибки входа от ошибок формирования результата, не определять HTTP-статус по числу внутри текста исключения.

Первые два пункта объясняют основную массу падений. Ожидания тестов сохранены по v7; сервисный Java-код в этом запуске не исправлялся.

## Инфраструктура и данные

В начале старта Kafka были сообщения `NOT_COORDINATOR`; затем consumer успешно вступил в группу, получил назначение partition и продолжил работу. Они предшествуют тестовому интервалу и не являются причиной 77 ответов 500. В интервале прогона нет ошибок подключения Ignite или загрузки справочников. NPE, ошибки чтения JSON и обязательных полей подтверждены стеком самого сервиса.

После каждого прогона проверены кэши: `splitting_object_cache=0`, `splitting_field_cache=0`, `actualization_cache=0`. В `param_cache` и `data_source_cache` по одной базовой записи MAPPER, загруженной при старте. Валидационные запросы не создали данных, очистка объектов не требовалась.

Сценарии с D1/SP1/SP2, создание объектов через REST и их teardown в этот прогон не включены: они ещё не реализованы в основном наборе. Локальный Apache-клиент теперь доступен, но его наличие не доказывает совместимость с корпоративным Ignite SE.
