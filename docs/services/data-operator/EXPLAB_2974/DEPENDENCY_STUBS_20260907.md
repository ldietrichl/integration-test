## Контракт и границы

Основание: Feign/DTO/ingestion-код архива `06fd6acb646`, полная ФП ExpLab v17 (метаданные параметров и источников, стр.2707+ и 2776–2781), D1 из плана endpoint v7. В ФП справочник источников вызывается GET и содержит схемы-объекты; архивный клиент использует POST и строковые схемы. Заглушка поддерживает обе формы отдельно и соблюдает фильтрацию.

Обязательные для D1 поля, ключи, JSONPath и полные схемы заполнены. Сплиты E1/E2 синтетические, GET фильтруется по int64 ids. Поведение ошибок самой заглушки описывает поддержанный тестовый контракт, а не весь интерфейс корпоративных сервисов. Kafka работает в стенде, но этот прогон загружает объекты REST dev-методом и не подтверждает цепочку Kafka producer → consumer.

Источник данных тестовой точки нельзя добавить существующим refresh REST: код запрашивает только MAPPER. Для двух уникальных точек применяется ограниченная запись `DataSourceDictCacheEntryMapper` через Ignite thin client. Объекты создаются исключительно REST-запросами. Удаление собственных данных через Ignite — второй документированный fallback, поскольку REST delete в исследованных материалах не найден. SQL/общая очистка кэшей не используются.

Helper подключается только к адресу loopback выбранного стенда, без discovery внутренних Docker-адресов, с ограничением времени ожидания. Точки проверяются по точному UUID манифеста; все библиотеки helper извлекаются из проверенного JAR, без замены сервисного кода.

Первый диагностический запуск прервался после загрузки SP1: REST dev-метод вернул `text/plain`, а подготовка ожидала JSON. Разбор Content-Type исправлен. Остатки этого частичного запуска удалены по сохранённому манифесту; последующие D1 и изоляционная проверка завершились с автоматической очисткой.
