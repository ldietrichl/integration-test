## Состояние инфраструктуры и предел результата

Первая попытка SL-01 прошла саму HTTP-проверку, но служебное чтение `splitting_object_cache` зависало до/после неё. Этот запуск сохранён отдельно (`run-fixture-20260907-214544-670`) и не включён в итоговые 104 результата. В Ignite обнаружен заблокированный системный поток; дамп показывает ожидание записи лога через `FileOutputStream`. Команды Docker/WSL тоже перестали завершаться.

После подтверждения пользователя выполнен перезапуск Docker/WSL. Ошибка `sailor-ingest.sock` устранена переименованием двух каталогов временных сокетов в резервные копии, без factory reset/удаления образов или томов. Восстановлены пять ранее работавших контейнеров; оба data-operator достигли UP, `mapper-splitter-lab-control-plane` подтвердил Ready. Затем повторно выполнены D1 и негативная часть.

**До начала негативной части Kafka завершилась с кодом 1.** Docker сообщил `read-only file system` при чтении файла контейнерного лога. На диске C: во время диагностики оставалось около 1,7 ГБ; причинная связь с переходом файловой системы в read-only пока не доказана. Ignite и HTTP data-operator позволили исполнить все 104 проверки; endpoint links работает с Ignite, а D1 загружается через REST. Поэтому фактические ответы валидны для этого локального пути, однако полностью исправным стенд считать нельзя, Kafka-цепочка не подтверждена.

Анализатор доработан: остановленный контейнер из манифеста теперь отмечается как инфраструктурная проблема даже при доступном HTTP. В итоговой сводке явно сохранён `kafka (exited)`; ошибки контракта не превращены в успешные проверки. Код сервиса не менялся, проверены 74 исходных Java-файла относительно архива.
