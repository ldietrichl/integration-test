# EXPLAB-2974: исправления архитектуры тестов и локального стенда

Область согласована с пользователем: тестовый проект и локальный стенд. Java-код data-operator и ожидания v7 не менялись. Ветка — `feature/EXPLAB-2974-data-operator`.

| Проблема | Исправление | Проверка |
|---|---|---|
| Порты и версии передавались в нескольких независимых аргументах и файлах | Общие профили для start/run/report/stop; привязка рабочего каталога к профилю и конфигурации | Неверный профиль отвергается; перезапуск compatible сохраняет работающий local |
| PID мог уже принадлежать другой программе; открытый порт считался готовностью | Проверка PID + времени создания + командной строки, проверка health и метаданных собственного процесса | Тест устаревшей записи PID и занятого чужим процессом порта |
| Start, stop и тесты могли одновременно менять один стенд | Блокировка операции на уровне рабочего каталога | Вторая операция отвергается, блокировка освобождается в finally |
| REST-тесты наследовали базу с DB-flow | Выделен `RestFlows`; существующий `Flows` наследует REST-фабрику и сохраняет DB-фабрики | Компиляция прежних Flows и всех основных Java-исходников вне независимого AI-модуля |
| Classpath зависел от содержимого всего Gradle cache | 121 фиксированная библиотека с SHA-256, согласованные Jackson/JUnit/Groovy, удалены дубликаты и посторонние AI-зависимости | Проверки повторной версии и неверного SHA-256; реальная компиляция и прогон |
| Старые class-файлы могли попасть в следующий запуск | Отдельный новый каталог классов и явная область исходников на каждую компиляцию | Новый манифест классов/исходников/lock-файла для прогона |
| HTTP-ответы извлекались регулярными выражениями из консоли | JSON-артефакт запроса/ответа до assertions, связь с JUnit ID, вложение в Allure | 103 HTTP-артефакта для 103 вариантов; офлайн-анализ без scenarios.log |
| Число 103 было зашито в runner и анализатор | Число вариантов из каталога запросов, контроль полноты и регистрация пропусков/ошибок контейнеров | Набор из одного/двух вариантов в проверках анализатора; полный текущий набор 103 |
| Анализ результатов требовал работающий сервис | Сбор состояния в run-tests.ps1; анализатор читает только сохранённые файлы | Тесты без сетевых вызовов; поддержка не-JSON ответа и отсутствующего HTTP-артефакта |
| Подмена версии окружения и повторное использование старого JAR могли остаться незаметными | Проверка неизменности 74 Java-файлов, версий зависимостей, SHA-256 POM/JAR и фактических image ID в манифесте | Успешный проверенный старт и повторный старт без лишней сборки |

## Результаты проверки

- **9** регрессионных проверок анализатора/lock-файла.
- **4** проверки управления стендом: конкурирующая операция, чужой профиль, устаревший PID, занятый порт.
- **22/22** существующих unit-проверки фабрики запросов и строгих assertions прошли на новом classpath. Компиляция проверки включила 217 файлов, в том числе прежний `Flows` и вызов унаследованной REST-фабрики.
- Compatible остановлен и запущен заново; все три процесса исходного local-стенда продолжили работу, health local остался UP.
- Реальный flow/rest-прогон: **103/103 выполнено**, для каждого есть отдельный HTTP-артефакт. Инфраструктурных проблем — **0**. Все HTTP-статусы и вердикты совпали с прогоном до рефакторинга: 77 × 500, 24 × 200, 2 × 400 с нарушенной схемой; **0 passed, 103 failed** по контракту сервиса.

Падения сервиса сохранены как найденные дефекты. Рефакторинг тестовой архитектуры не делает их успешными проверками. Промежуточный запуск при уточнении classpath выявил недостающий Freemarker; анализатор классифицировал отсутствие HTTP-доказательств как инфраструктурную проблему, библиотека затем явно добавлена в lock.
