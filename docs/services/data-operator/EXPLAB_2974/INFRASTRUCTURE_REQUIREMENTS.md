# EXPLAB-2974: чего не хватает и чем можно помочь

Локальный контур уже поднят и проверен: data-operator из архива, Apache Ignite, Kafka, H2 и заглушки ответов dictionaries/experiments. Для повторения текущих 103 валидационных запросов дополнительных файлов не требуется. Два прогона состоялись; выявленные падения объясняются кодом сервиса и его логом.

Дополнительно скачаны и испытаны альтернативные публичные версии: **Ignite 2.18.0 + Kafka 3.9.1**, с совпадающей версией клиента и сервера Ignite и клиента/брокера Kafka. Третий прогон дал те же 103 падения. [Результаты сравнения](COMPATIBLE_VERSIONS_RUN_20260907.md). Для продолжения локальных проверок помощь с установкой сейчас не требуется; перечисленные ниже артефакты нужны для проверки корпоративных отличий и настоящих соседних сервисов.

Ниже — недостающие компоненты для окружения, соответствующего корпоративному развёртыванию, и для следующих частей плана.

Точные закрытые Maven coordinates из POM архива:

```text
com.sbt.ignite:ignite-core:17.6.0
com.sbt.ignite:ignite-indexing:17.6.0
com.sbt.security.ignite:security-core:17.6.0
com.sbt.security.ignite:security-ldap:17.6.0
```

Достаточно указать путь к папке с артефактами. Для передачи подготовлен каталог:

`A:/Codex/Functional/BACK/01_reference_sources/data_operator_service/EXPLAB-2974-dependencies/`

Полезно приложить список версий или исходных commit/image digest. Один `.jar` без транзитивных зависимостей может оказаться недостаточным. Файлы секретов не требуется добавлять в Git; используем существующий механизм локальных настроек.

Системных действий от администратора для работающего локального контура сейчас не требуется. Docker восстановлен без factory reset; открытый административный PowerShell для этого не понадобился.

Отдельно от инфраструктуры остаются U1–U6 из endpoint-плана: неоднозначности имён JSON, пустых rules, отсутствия кэша, LIKE, ошибок 422 и форматов DATE/DATETIME. Их лучше закрывать решениями владельца требований, а не подгонять ожидания под фактическое поведение кода.
