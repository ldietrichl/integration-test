h1. [EXPLAB-3109] В Kafka отсутствует deletedLinks при фактическом удалении связи эксперимента с кампанией

h2. Описание

При обработке задачи обновления связей experiment-service удаляет существующую
связь из БД, но событие чанка в Kafka ExpLab не содержит её снимок в deletedLinks.
Итоговое событие сообщает executionError=false. По журналу невозможно восстановить
факт и содержимое удаления связи, хотя операция в БД выполнена.

h2. Окружение и прогон

* Стенд: ИФТ.
* Дата: 23.10.2026.
* Прогон: 20261023-215526-138-ecad21a9.
* Тест: ExperimentLinksCore3109FlowTest.test29 — «Удаление собственной связи публикует достоверный deletedLinks».
* Топик Kafka: exp-cj-links-update-log.
* Результат общего прогона: 12 тестов, 11 PASS, 1 FAIL; единственный FAIL — test29.
* Подготовка и очистка всех 12 тестов завершились успешно.
* Воспроизводилось на реальных данных ИФТ; размер чанка и страницы не изменялся.

h2. Предусловия

# Создан собственный тестовый эксперимент с конфигурацией, связанной с реальной кампанией.
# В БД подготовлена одна собственная связь этой конфигурации с выбранной кампанией. В test29 она вставлена напрямую в БД с реальными наборами Campaign, а не создана пересчётом для проверяемой конфигурации. Её ID и четыре набора сохранены до задачи.
# Конфигурация исключает все фактически полученные WORKING-коммуникации выбранной кампании.
# Независимый запрос Campaign Service подтверждает HTTP 200, configScope именно этой конфигурации, isLastPage=true и cjs=[]. В последнем прогоне пустой результат подтверждён дважды до задачи и повторно после неё.
# Включено штатное выполнение обновлений, обеспечен доступ к Kafka ExpLab и согласовано окно выполнения без сторонних изменений тестовых данных.

h2. Как подготовлены данные в test29 и граница бизнес-покрытия

Сначала для первого собственного эксперимента выполняется настоящее обновление
с непустыми реальными данными Campaign. Затем создаётся второй собственный
эксперимент, в конфигурации которого исключены все найденные WORKING-коммуникации.
Независимое чтение Campaign подтверждает пустой результат для второго конфига.

После этого связь второго конфига подготавливается прямой вставкой в БД; четыре
набора берутся из независимого реального Campaign-снимка первого эксперимента.
Проверяемая task27407 ставится через штатный HTTP endpoint уже после подготовки.
Удаление выполняет настоящий сервис; события и ответы источника не подменяются.

Тест проверяет обновление и журнал для состояния «существующая связь есть, текущие
условия больше не дают кампанию». Полный пользовательский путь возникновения
этого состояния — первоначальное создание связи сервисом и последующее изменение
условий для того же эксперимента через штатные интерфейсы — в test29 не выполнен.
Поэтому данный результат не следует представлять как подтверждение такого полного
бизнес-пути. Проверенные факты: подготовленная собственная строка существовала,
сервис удалил её, а соответствующего deletedLinks в событии не оказалось.

ID ниже относятся к последнему выполненному прогону. Тестовые объекты удалены
успешной очисткой; для повторения необходимо создать новые собственные объекты
и использовать их идентификаторы.

h2. Ожидаемый результат

* Исходная связь удалена из БД при подтверждённом пустом результате Campaign Service.
* Событие чанка соответствующей задачи и конфигурации содержит totalLinksFlushed.deletedLinks с полным снимком удалённой связи: прежний ID, cjId, productCrmIds, channelIds, templateIds, commIds.
* Снимок соответствует состоянию связи до запуска задачи.
* При единственном удалении отсутствуют ложные createdLinks и updatedLinks.

h2. Фактический результат

* До задачи в БД присутствует связь id=531120, configId=4334, cjId=106658 с указанными выше наборами.
* После завершения task27407 выборка связей для этой конфигурации и кампании пуста.
* В фактическом событии чанка totalLinksFlushed={} — deletedLinks отсутствует.
* Итоговое событие той же задачи содержит executionError=false.
* test29 завершился FAILED на проверке соответствия deletedLinks фактическому удалению из БД.

{code:json}

  "configIds": [4334],
  "totalLinksFlushed": {}

{code}

h2. Влияние

Kafka-журнал не отражает фактически выполненное удаление. При восстановлении
процесса обновления связей по событиям теряется информация об удалённой связи,
при этом итоговое сообщение сообщает успешное завершение обработки.
