h1. EXPLAB-3109 — выбор writable primary после переключения БД

23.10.2026 получено подтверждение автоматического переключения primary ИФТ
с1637 на1636. В API-прогоне20261023-150916-956-3dfe807f использовался одиночный
адрес1637 и targetServerType=master; все пять prepare остановились при открытии
соединения. Бизнес-проверки POST/GET и Kafka в этом прогоне не выполнялись.

h2. Изменение профиля

Изменён только db.ift.explab.url в src/test/resources/database.properties:

jdbc:postgresql://tvldd-mvp001636.delta.sbrf.ru:5433,tvldd-mvp001637.delta.sbrf.ru:5433/abtm?prepareThreshold=0&targetServerType=master

Указаны оба известных узла,1636 первым. PostgreSQL JDBC при открытии нового
физического соединения проверяет кандидатов с требованием primary. Подключение
не должно приниматься к узлу, который драйвер определяет как read-only/standby.
Проверка pg_is_in_recovery()/transaction_read_only в штатных шагах сохранена.
Выбор узла при открытии соединения не восстанавливает уже оборванную транзакцию.

Сохранены порт5433 для обоих узлов, БД abtm, prepareThreshold=0,
targetServerType=master, прочие профили, pool/таймауты и ссылки на учётные данные.
Не добавлены новые параметры retry/load balancing. Пароли и секреты не поставляются.
Остальные байты файла сохранены; только одна строка URL расширена списком узлов.
stand.properties, код тестов, Gradle и Kubernetes-настройки не меняются этим патчем.

h2. Установка и проверка

Небольшой патч применяется поверх установленного V7, не заменяет девять тестов.
INSTALL_CORP.md содержит проверку известных исходных SHA256, резервную копию,
повторную установку и откат. Неизвестная версия database.properties блокируется
до записи; её настройки надо сверить, а не перезаписывать принудительно.

Локальная проверка доступного PostgreSQL JDBC42.7.7 подтвердила Driver.parseURL:
PGHOST содержит1636,1637; PGPORT=5433,5433; PGDBNAME=abtm;
prepareThreshold=0 и targetServerType=master сохранены, master — алиас primary.
Проверка не вызывала connect и не обращалась к сети. Версия корпоративного runtime
JDBC JAR из предоставленного build не установлена. Реальное переключение сообщено
из среды; этим локальным разбором оно не выполнялось и не моделировалось.

После установки запустить новый процесс Gradle:

.\gradlew.bat explab3109Api

После успешного API-прогона отдельно выполнить explab3109Kafka. Между наборами
не выполнять clean. Не менять full-log/improve/dedup, размеры чанка и страницы.
ИФТ-прогон20261023-160030-602-6e567df8 подтвердил ресурс с двухузловым URL
и успешную проверку primary/readOnly во всех пяти API-методах. Бизнес-PASS пока
не подтверждён: далее запросы получили401 с просроченным JWT.
