h1. EXPLAB-3109 — ядро V7: два API и Kafka ExpLab, 23.10.2026

h2. Результат изменения

Core теперь содержит 01/09/18/60/61 и22/23/26/27: три проверки ручного POST,
две проверки GET текущих задач и четыре проверки публикуемых событий. Контракт
подтверждён предоставленным feature-EXPLAB-3109@1095ea3be01;21 относящийся файл
сверён с архивом побайтово. Поддержка этого контракта развёрнутым образом359
проверяется следующим стендовым запуском, а не считается доказанной исходниками.

POST /api/v1/experiments/cj_links/update проверяется по задаче, а не только HTTP200.
Последовательный дубль ожидающей задачи не создаёт новую запись. POST без тела
возвращает400 и не меняет очередь. GET /api/v1/experiments/cj_links/update/status
показывает текущие задачи: [] для пустой очереди, полный DTO и id ASC для непустой.
Список не является историей завершённых задач и не имеет пагинации.

Kafka-проверки используют настоящий consumer и offsets всех partitions до задачи.
Итог, реальные чанки/страницы, createdLinks и updatedLinks проверяются по scoped
taskId и независимым данным. Одинаковые повторно доставленные payload не требуют
exactly-once. Нет требований к глобальному порядку разных partitions или Kafka key.
Ошибочное/недостигнутое выполнение не отмечается успешно проверенным.

h2. Подготовка и переиспользование

18/60 не создают барьер, фикстуры, Kafka consumer или workload-сеанс и не обращаются
к Campaign/Kubernetes. Остальные используют общий Environment/Fabric8, Workload
lifecycle, lease и собственный барьер. Профиль сохраняет текущие job/периоды
(true/10/600 в предоставленном ConfigMap), не назначает1/3600. Full-log/improve/dedup
не требуются и не меняются для scoped-задач. Размеры чанка и страницы не задаются.

Для Kafka размер страницы берётся из фактического журнала запроса. Существенный
запрос строится независимо из собственного DTO; Campaign-ответ повторно читается
напрямую и проверяется на стабильность. Числовые IntNode/LongNode нормализуются как
одно целочисленное JSON-представление; строки, дробные числа и значимые поля остаются
различимыми. Созданный snapshot id допускает null/отсутствие до сохранения; назначенный
id проверяется. Updated snapshot сохраняет существующий id и исходные значения;
достаточно реального изменения одного набора. Условия четырёх непустых наборов,
обязательных двух страниц и намеренного5xx удалены из ядра.

Прежние сценарии25/39/47/51 и неиспользуемые новым планом assertion-методы
удалены из Core. Самостоятельный регресс пересчёта не входит в новое ядро; общие
helpers, HTTP/БД/Kafka шаги и механизм результатов переиспользованы.
Методы01/22/23/26/27 сохранены для истории. Новые09/18/60/61 добавляют API-покрытие.
Только собственные объекты создаются/изменяются/удаляются; writable primary, реальная
изоляция, защита чужой очереди и правила незавершённой очистки остаются обязательными.

h2. Запуски и поставка

explab3109Core выбирает9, explab3109Api —5 API-методов,
explab3109Kafka —4 Kafka-метода; explab3109ExistingData совместимо выбирает те же5 API.
Каждый набор запускается отдельным вызовом Gradle. Нельзя объединять два набора,
полный регресс или clean в одном вызове. Для накопления raw между прогонами не
выполняются clean/cleanRegressionResults/cleanAllureResults. Общие сборщик результатов,
Allure и подготовка TestOps сохранены; отдельного uploader нет.

V7 готовится как поставка полных файлов с manifest, guards известных SHA256,
backup и откатом. Известные предыдущие версии и новые payload сверяются до записи;
неизвестные корпоративные изменения не перезаписываются. Полный stand.properties
и общий архитектурный документ не заменяются. Существующие значения конфигурации
сохраняются, недостающие разрешённые ключи добавляются по правилам установщика.
Финальный состав/проверки пакета определяются его manifest и INSTALL_CORP.md.
Готовность исходников не означает, что архив выдан, установлен или проверен на ИФТ.

h2. Проверки и границы доказательств

Локально без сетевых/стендовых вызовов прошли:
* JDK17 javac компиляция18 актуальных изменённых Java-исходников;
* 34 проверки assertion-слоя: неверные GET/очередь/типы/nullable поля, scoped correlation,
  независимые запросы/ответы, допустимый null id новой связи, неверные/изменённые id,
  независимый старый snapshot, повторная доставка и целочисленные JSON-представления;
* общий TestReportEligibilityScanner с актуальным SchedulerRegressionPolicy: все9
  методов допущены при env=ift/functionalonly/rest, старые25/39/47/51 отсутствуют;
* help реального модульного Gradle8.4 и проверки projectsEvaluated настоящего изменённого
  скрипта: Core9/Api5/Kafka4/ExistingData=Api5, последовательный запускИФТ, отсутствие
  старых задач и запрет несовместимых комбинаций.

Gradle проверялся через офлайн-адаптер: подключён доступный локальный plugin repository,
недоступные корпоративные зависимости заменены имеющимися библиотеками. JVM выполнялась
в том же процессе из-за ограничения localhost daemon. Это проверка реального модульного
build и выбора задач; не полный корпоративный Gradle dependency resolution/testClasses,
не проверка Nexus и не выполнение функциональных тестов.

Новый ИФТ-прогон V7, доступность GET в359, права записи фикстур, успешные config-details,
Kafka-доставка/снимки и бизнес-PASS пока не подтверждены. Последний пользовательский
прогон V6 остановил все пять методов в prepare. Установка V7 и импорт TestOps не подтверждены.
