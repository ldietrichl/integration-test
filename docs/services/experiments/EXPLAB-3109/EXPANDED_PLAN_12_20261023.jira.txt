h2. Исправленные недостатки assertions

* Long: config/campaign/task/request IDs строго целые, в диапазоне Long и положительные
  там, где ID обязан быть положительным; строка, дробное и overflow не принимаются.
  hostname обязан быть непустой строкой. Начальные счётчики ограничены Integer.
* Только productCrmIds/channelIds/templateIds/configCommIds CampaignConfigDto
  сравниваются как типизированные множества. Остальные структуры, страницы,
  порядок списков и существенные параметры запросов сохранены точными.
* Полный totalLinksFlushed проверяется относительно независимой БД до/БД после
  и отдельного Campaign. Созданные, изменённые, удалённые действия проверяются вместе,
  включая отсутствие ложных действий и сохранение ID существующих связей.
* У всех наблюдённых событий чанков своей задачи проверяется допустимый config scope
  до выделения завершённой попытки. Повтор одинакового payload не считается
  самостоятельным действием; exactly-once и общий порядок partitions не вводятся.
* request_dt сравнивается с независимым интервалом часов primary БД вокруг POST,
  с явным допуском ±30 секунд для приложения/БД. Переполнения границ отклоняются.
* После удаления своего барьера и задач выполняются SELECT постусловия; в конце
  подтверждено отсутствие всех зарегистрированных собственных экспериментов, конфигов, связей, задач и owner-маркера.
  Незнакомая задача останавливает очистку; полная очередь не удаляется.

h2. Реальное выполнение 28/29/30

Общий этап: прежняя подготовка через Environment/Workload; Kafka observer после
Ready/проверки configured binding и до DB/HTTP fixtures; свой барьер; собственный эксперимент;
ограниченная реальная задача с watchTask до release. Независимый Campaign и БД подтверждают
первичный результат и наблюдаемый page size. Задача должна уйти из очереди.
Возвращается только прежний свой барьер с меньшим ID, чтобы подготовить следующий этап.

28: перед повтором независимые данные читаются дважды; тот же ограниченный запрос
должен создать новый taskId. Журнал/источник/дельта проверяются; link IDs и наборы
не меняются, все 3 массива действий пусты либо отсутствуют по NON_NULL. Технические
hostname/requestId/время разных задач не должны быть одинаковыми.

29: создаётся новый собственный эксперимент с фильтром, исключающим настоящий id-list кампании.
Только после независимого HTTP 200 с точным собственным configScope, isLastPage=true и cjs=[] и повторного
подтверждения готовится своя DB связь из фактических наборов первичного источника.
После задачи снимок deletedLinks обязан точно совпасть с БД до по ID/CJ/всем 4 наборам,
БД после должна быть пуста, created/updated не допускаются. Отсутствие snapshot при
фактическом удалении — дефект. Вероятный дефект source1095 не отменяет assertion.

30: два новых собственных эксперимента, по одному config; live id-list должен содержать ≥2 IDs.
Каждый фильтр исключает всё, кроме одной разной реальной коммуникации. Два независимых
непустых разных набора подтверждаются дважды до POST. Ставятся две задачи под барьером,
оба taskId регистрируются observer до release. Завершаются обе, затем для каждой отдельно
проверяются task/config/страницы/реальные ответы/дельта своей области БД. GET сверяется
после завершения обеих, чтобы избежать сравнения изменяющейся очереди.

Все POST ограничены собственными expIds и реальным cjId. Никакие размеры/периоды job/producer
не меняются. Подготовка DB seed для 29 — собственный настоящий объект с проверенными
данными, не подмена ответа Campaign и не фальсификация функциональных результатов.

SHA256 до замены, резервирует и поддерживает точный откат с контролем чужих изменений.

h2. Проверки и границы

Компиляция актуальных исходников Java 17 и локальные replay/mutation checks выполняются
без инициализации Environment и стендовых операций. Они проверяют assertions
на реальных сохранённых данных и изменённых копиях, но не доказывают live удаление,
два новых фильтра или no-op сервиса. Эти результаты не входят в Allure/TestOps.
Настоящий изменённый модульный Gradle проверяется офлайн для selections/guards,
а не повторением логики реестра в подставном скрипте. Полный корпоративный testClasses
и новый набор 12 на ИФТ ещё нужны. Прежние неизменяемые ZIP и raw прогоны сохранены.
