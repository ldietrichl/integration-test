h2. Строгое удаление и остающиеся риски

В предоставленном source1095 addDeletedToLog:393–395 имеет return при
needProcessingLog=true, хотя удаление БД:243–250 выполняется. В новом прогоне
цепочка подтверждена: собственная исходная связь есть, источник возвращает пустой
scoped200, связь исчезла из БД, итог успешный, deletedLinks отсутствует. После исправления порядка ID
новый29 дошёл до проверки delta и упал на отсутствующем deletedLinks. Снимок
по-прежнему обязан содержать исходный ID и все наборы. Сервисный код в патч не входит; изменение ожидания ради PASS запрещено.

Одна страница допустима. Multipage при неизменном размере требует другого
реального объёма; retry/5xx и прерывание job требуют согласованного сбоя/восстановления;
прогресс counters/currentState требует долгой задачи. Эти ветви не выдаются за покрытые.
Pod логи собираются общим механизмом; стабильный контракт конкретных сообщений
не задан, поэтому их наличие само по себе не является бизнес-assertion журнала Kafka.
