# Excel: пользовательские сценарии запуска

Источник: «сценарии запуск.xlsx», Лист1, 24 номера UC. UC-08/09 в файле отсутствуют.
Дополнение содержит 20 сценариев в `experiments/EXPLAB_2972/launch_plan`.
UC-10/15/21/22 используют существующие TP-01/02, TP-28/29, TP-34, TP-35 соответственно; повторные тесты одинаковой бизнес-проверки не добавлены.
Сопоставление относится к API-поведению. Проверки различий ролей выполняются от отдельных пользователей стенда.

Используются обычный test sourceSet, Platform V AT Environment, Flows, FixtureService, RestService, DatabaseService, Allure и существующий контроллер управляемых сценариев. Отдельного HTTP/SQL test runner нет. Локальные скрипты подготовки не входят в корпоративный пакет.

## Пользователи

| Профиль | Роли | Назначение |
|---|---|---|
| primary | expCreator, spMAPPER | Инициатор простого эксперимента |
| approver | expValidator, spMAPPER | Другой пользователь, согласующий простой шаблон |
| admin | adminSp, spMAPPER | Администратор точки MAPPER |
| operator | smartExpCreator, spMAPPER | Отдельный владелец запускаемого/останавливаемого эксперимента |

«Оператор» — обозначение из Excel, а не выдуманная роль user-service. Фикстура MODEL_TEST должна быть простым шаблоном на MAPPER, доступным указанным ролям. Проверка UC-14 дополнительно отклоняет запуск чужого эксперимента инициатором, затем запускает его от владельца.

В `test.properties` выбираются `env` и профиль. Режим users.mode:

- `api`: заранее выделить четыре IAM subject и получить действующие токены обычным способом стенда. Тест создаёт/обновляет только пользователей с логином EXPLAB-2972-*, проверяет существующие subject/логин/роли перед изменением; после POST читает запись и получает ID из permissions. Если user-id не задан, использует полученное значение внутри текущего сценария. Возвращаемый API ID нельзя предсказывать по порядку вставки.
- `prepared`: существующие отдельные пользователи. Тест проверяет их ID, роли и совпадение sub с токеном. Подходит и после согласованной подготовки через БД, когда операция создания внутреннего API недоступна; чтение users/subs и users/permissions всё равно необходимо.
- `local-db-adapter` запрещён для корпоративных сред; использовать только api или prepared.

Токены разрешаются штатным SecurePropertyResolver только из игнорируемого `secure.local.override.properties`. `secure.local.properties` — шаблон; env/JVM/gradle.local не являются источниками секретов. В `test.properties` остаются ссылки `${SECURE_...}` на токены и логины, роли, sub, фактический user-id и параметры сценариев. Значения логинов задаются в override; API-подготовка допускает только выделенные имена с префиксом `EXPLAB-2972-`. Значения токенов не следует помещать в отчёты. Проверка sub/exp в тесте не является проверкой подписи JWT; подпись проверяет инфраструктура корпоративного стенда. Тест не создаёт корпоративные токены.

## Расширение контроллера

Дополнительно к CONTROL-API.md:

- capability `mapper-switch`: POST sessions/{id}/mapper `{disabled:true|false}` меняет настоящий серверный флаг и дожидается готовности сервиса; close восстанавливает исходное состояние.
- capability `scheduler-delete-faults`: fault `{mode:"scheduler-delete-503"}` обеспечивает 503 только для удаления запланированных задач. close снимает отказ.
- capability `scheduler-execution`: scheduler-execute `{taskId,expId}` освобождает scheduler для указанной задачи после наступления endDt, сохраняя jobs конфигураций остановленными. Контроллер не подменяет состояние в БД. observations содержит фактическую задачу и её COMPLETED. taskId сохраняется в исходном типе, включая UUID. `/capabilities` явно возвращает `schedulerImplementation=real|stub`; stub допускается только локально и обозначается в Allure.
- Реальный scheduler отправляет POST status/bulk с requestSource=AUTOTASK_JOB и userId=task.createdBy. Успешность задачи scheduler и достижение экспериментом STOPPED проверяются раздельно.

Отсутствующая возможность — ошибка предусловий (Allure broken / отчёт BLOCKED), не пропуск и не PASS. Контроллер не возвращает готовый вердикт вместо проверки API/БД.
