# Scheduler: исполняемый регресс на реальном тестовом стенде

Дата: 18.09.2026.

## Принятое ограничение

Только реальный тестовый стенд и реальные зависимые сервисы. Заглушки, WireMock и отдельный искусственный контур не используются. По решению пользователя неподготовленные для этого контура сценарии удалены из исполняемого кода, но оставлены в полном тест-плане `src/test/resources/scheduler/scenarios.json`.

Удаление из кода не означает отмену требования, успешную проверку или невозможность реализовать сценарий в будущем.


## Подготовка и безопасность

- Используются существующие REST/flow/DB-степы и общие настройки выбранного стенда.
- Подготовка фикстур выбирает два различных действующих ID пользователей из БД. Жёстко заданные пользовательские ID не добавлены.
- Сценарии с фикстурами используют существующее управляемое приостановление фоновых заданий, сохранение предыдущих значений ConfigMap и восстановление после класса.
- Удаление pod и изменение ConfigMap требуют ранее предусмотренных явных разрешений выделенного стенда. Защитные проверки не отключены.
- Настройки `stand.properties`, `test.properties`, kubeconfig, сертификаты и секреты этим патчем не заменяются.
- Удалены устаревшие `scheduler.prepared.*`; механизм ручного prepared-каталога больше не участвует в регрессе.
- Включение сценария не гарантирует успешную подготовку окружения. Ошибка подготовки остаётся ошибкой, а существующая защита зависимых сценариев может прервать их выполнение. Продуктовые assertion failures не превращаются в успешные или отключённые тесты.
- Не выполняются изменения в коде scheduler-service.

## Что изменено в сценариях

SCH-014 создаёт собственные записи для двух пользователей и проверяет положительный контроль обычного реестра. Запрос MY_TASKS без прикладной авторизации должен вернуть 401/403 либо пустой результат; 500 и утечка чужих записей не принимаются. Авторизация OpenShift этим запросом не меняется.

SCH-LIVE-015 проверяет NEAREST_PLANNED: будущие PLANNED, исключение прошлого и неверного статуса, точный состав и порядок.

SCH-LIVE-017 проверяет LAST_ERRORS: прошлые ERROR, исключение будущего и неверного статуса, точный состав и порядок.

Часы берутся из реальной БД; свидетели разнесены на часы от текущего момента. Это не проверяет исходные SCH-015/SCH-017 с фиксированным временем и точной границей T/T±1ms. Исходные случаи остаются пробелами плана. Изменение или пропажа собственных записей также проверяются.

## Покрытие: без завышения

Исходный план содержит 137 сценариев. Исполняемый код сохранён для 54 из них; 83 оставлены только в плане.

`54 / 137 = 39,42%` является долей исходных сценариев с кодом, а не процентом функционального покрытия и не процентом успешно пройденных тестов. Дополнительные live-проверки и preflight не увеличивают числитель исходных полностью реализованных сценариев.

Цель более 80% функциональности этим изменением не доказана. Для её подтверждения нужны полная трассировка требований, реализация оставшихся воспроизводимых предпосылок и результат корпоративного прогона. Строки плана и знаменатель не сокращались.
