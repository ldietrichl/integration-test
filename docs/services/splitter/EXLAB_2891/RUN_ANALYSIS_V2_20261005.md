## Allure: исходные данные и HTML

- Общий `build/allure-results`: 106 результатов (100 passed, 6 failed), 4169 файлов, 8 520 590 байт.
- Это два прогона по 53: прежняя v1 и новая v2. Пропавших вложений и ссылок children на отсутствующий результат нет.
- Для каждого из новых 53 результатов есть plain-text лог pod с exactOperationWindow=true и mayBeTruncated=false;
  также присутствуют metadata и снимки управляемых ConfigMap.
- Существующий HTML `build/reports/allure-report/allureReport` показывает статистику 53/50/3; после ошибки генерации он не обновился.

Причина двух падений allureReport в shell.txt:

```text
Allure: Target directory ...\build\reports\allure-report\allureReport
for the report is already in use, add a '--clean' option to overwrite
```

Генератор завершился с exit code 1, потому что каталог предыдущего отчёта уже существует.
Падения функциональных тестов и целостность JSON не являются причиной этой ошибки.
У используемого Gradle-плагина Allure 2.11.2 проверен параметр задачи `clean`;
его значение по умолчанию false, назначение — очистка только каталога HTML-отчёта.

Из корпоративного проекта выполнить:

```powershell
.\gradlew.bat allureReport --clean
```

Raw-файлы `build/allure-results` сохраняются. Не выполнять `.\gradlew.bat clean allureReport`:
отдельная Gradle-задача clean удаляет build с исходными результатами.
В новом HTML могут быть объединены повторные исполнения согласно historyId; 106 raw-файлов не означают 106 независимых тест-кейсов в интерфейсе.
Перегенерация в корпоративной среде здесь не запускалась; причина установлена по логу и реализации плагина.
