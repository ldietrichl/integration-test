# Проверка ассершенов EXLAB_2891 — 05.10.2026

Основание: спецификация v16 от 03.10.2026, код SDK 0.12.3 и присланные результаты MAPPER
(26 REST, 26 Kafka, 1 fresh). Исправления касаются тестов этой задачи.

## Найденные пробелы и исправления

| Проверка v1 | Риск | Изменение v2 |
|---|---|---|
| asInt/asLong для части полей | Строка, дробь или переполнение могли дать ожидаемое число | Только целочисленный JSON в диапазоне long, точное сравнение |
| Принадлежность возвращённых objectId запросу | Можно пропустить часть запрошенных объектов | Равенство множеств, отсутствие дублей; fixture включает empty-objects-response-enabled |
| Только MAIN и marker | Дубли ALL либо неверный actionType могли остаться незамеченными | MAIN и ALL: ровно один эксперимент, ожидаемые ID/группа/salt/слой; marker и actionType с точными типами/значениями |
| Предрасчёт: только soConfigVersion | Недостаточное подтверждение корректного тела ответа | Семь неотрицательных целых счётчиков, UUID responseId, версия; отсутствие errorCode |
| Сохранность таблицы после невалидного запроса | Частично добавленный объект без связей не обнаруживается одним split | Контроль состояния до запроса; проверки старых связей и нового ключа до повторной записи; повтор исходного набора требует copied=2, added=0, deleted=0 |
| Аргумент fields не использовался | Название шага обещало локализацию нарушения | Убран аргумент и исправлено название: проверяется HTTP-отказ и формат, а не перечисление полей в стандартной ошибке MVC |
| assertSame для исключений и обязательные детали | Корректная дополнительная обёртка/необязательное поле давали ложное падение | Семантическое сохранение цепочки, snapshot до вызова; errorDetails необязателен по документации |
| Любой Throwable при проверке старта | Ошибку reflection/зависимостей можно спутать с отказом валидации | Валидный контроль до/после; ожидаемая категория исключения; ошибки reflection/linkage/assertion отклоняются |
| Fresh: только дубликат | Нельзя отделить общий сбой актуализации от обработки дубликатов | Динамический контроль конфигурации, затем проверки уникального и повторяющегося сохранённых объектов |

Проверка UUID не доказывает независимость responseId от requestId. Этот вопрос не входит в задачу.
Полный стек не сравнивается побайтно: проверяются исходные типы/сообщения и сохранённые места возникновения,
дополнительные обёртки допустимы. Для готового SplitterException проверяются код, requestId, сообщение и ранее заданные детали.

## Проверка исправлений

- Java 17 / Gradle 8.4: компиляция всех 17 Java-файлов задачи на корпоративных main-классах и общем API v9.
- 49 локальных проверок инфраструктуры и ассершенов, включая повреждение счётчиков, пропуски/дубли объектов,
  дубли ALL, неверные параметры, потерю причин/стека. Эти проверки не являются результатами тестирования сервиса.
- Проверено подключение Gradle-задач к общему build/allure-results; OfflineChecks сохраняются отдельно.
- Повторное применение проверок к сохранённым ответам: 429 HTTP-пар + 26 Kafka load acknowledgements;
  633 проверки прошли, 3 выявили те же известные нарушения. Повторного обращения к стенду не было.

Сохраняются обоснованные падения: objectParams=[] принят HTTP 200 в REST и Kafka вопреки требованию непустого массива;
fresh после загрузки подходящей конфигурации вернул пустые objectResults для сохранённого объекта.
Новый контрольный объект fresh и дополнительные обращения в сценариях нужно выполнить на стенде: старый прогон их не содержит.
Компонентные проверки настоящего SDK не выполнялись: требуется бинарный SDK из тестируемой корпоративной сборки с зависимостями.
Изолированная компиляция не заменяет полный корпоративный testClasses.
