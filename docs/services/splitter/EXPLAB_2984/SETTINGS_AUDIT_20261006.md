# Аудит настроек EXPLAB-2984, 06.10.2026

Область: подключение MAPPER/REACTIONS, настройки Gradle и IDE, REST/Kafka config-load, ConfigMap, lease и отчётность. Проверены действующие профили 2690/2885/2891, общий StandSettings, bindings, задачи 2984 и общий splitter-reliability. Аудит не является новым стендовым прогоном.

| Область | Результат |
|---|---|
| Deployment/ConfigMap | Исправлено отсутствие defaults в WorkedGroupProfile. Имена разрешаются существующими профилями MAPPER/REACTIONS; явные настройки сохраняются. |
| Общие defaults | StandSettings содержит общий механизм; bindings 2885/2891 делегируют ему с сохранением публичных методов. Права mutations не добавляются. |
| Переопределения | Задачи 2984 передают существующие префиксы профилей из `-P`/`-D`; раньше передавался только новый префикс. |
| Окружение | Единственный селектор — `env` в test.properties. Удалена вводящая в заблуждение передача env/file.env из задачи 2984. |
| Lease gate | Добавлена передача stand.* из `-P`; `-D` имеет приоритет. Команда остаётся read-only `check`. Автоматического снятия lease нет. |
| Нестандартные имена gate | Имена Deployment/ConfigMap предварительного gate задаются существующими workload.mapper/reactions параметрами. Они должны соответствовать тестовому профилю. Основная сессия повторно проверяет и получает lease на фактически используемых объектах. |

Причина первого стендового отказа: Gradle 2690 задавал имена ресурсов, а 2885/2891 устанавливали их через bindings; новая задача 2984 копировала свойства обычного test и не выполняла аналогичную подготовку. Рекомендация вручную дописать четыре ключа устраняла симптом, но не дефект подключения. В v3 отдельная настройка стандартного стенда для 2984 не требуется.

Введён только вложенный WorkloadPlan в существующий WorkedGroupProfile: он хранит идентичность ресурсов, разрешённую существующими профилями, без precalc-флагов и YAML. Новый Kubernetes-клиент или отдельный lifecycle не создавался.

Проверки: Java 17 на доступном корпоративном classpath; локальные проверки профилей, shared bindings, бизнес-assertions и архитектуры; реальные Gradle-скрипты задач и настройки read-only gate без запуска JavaExec на стенд. Полная сборка с корпоративным Nexus и повторный функциональный прогон не выполнены. Состав и результаты локальных проверок приводятся в инструкции поставки v3.
