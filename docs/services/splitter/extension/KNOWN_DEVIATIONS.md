# Splitter Extension: известные расхождения

Исторический общий DEV-прогон до разделения: 169 сценариев, 105 passed / 64 failed,
41м39с; 112/112 коррелированных Kafka-отчётов; все четыре ConfigMap восстановлены.
Это не результат новых 48 core / 125 extension. После time-flags полный набор стал 173,
его на DEV не запускали. Число зелёных тестов не равно покрытию требований.

| Расхождение исторического прогона | Наблюдение | Статус |
|---|---|---|
| no-MAIN | 35 сценариев общего набора возвращали MAIN[]; часть также ALL в REST | Нарушение согласованного контракта, конфликт текстов стр.96/98 отмечен |
| REACTIONS слои | 9 сценариев: один MAIN вместо трёх, например 269224 вместо 269224/269225/269226 | Свежая спецификация стр.183-184 подтверждает ожидаемый набор |
| Kafka ALL при allow=false | 20 DocumentDenied: 9 MAPPER, 11 REACTIONS; REST проходит, Kafka пуст | Спорный контракт, требуется решение владельца требований |
| resultDt | Во всех 112 отчётах 13-разрядное значение миллисекунд вместо microseconds | Ранее не обнаруживалось; усиленная проверка оставлена в extension |
| filtered | Проверка стала точной, добавлены AT2/AT4 | Дефект сервиса заранее не объявляется; нужен DEV |

Необязательное requestDt отсутствовало; это не ошибка доставки Kafka и не самостоятельный дефект.
Новых результатов DEV этот патч не создаёт. Ничего не исключено из extension ради зелёного отчёта.

Запускать splitterExtensionRegression отдельно. При полном успешном выполнении запросов
ожидаются 125 результатов, 116 Kafka-вложений, восстановленные ConfigMap/готовые поды,
освобождённые leases. Нельзя загружать build/contract-checks в TestOps.
