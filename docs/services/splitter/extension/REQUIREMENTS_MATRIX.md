# Splitter Extension: расширенная матрица

Источник: Тесты-v10-20261001_195337.pdf, описание split v1.3 и
Спецификации Сплиттера-v16-20261003_130355.pdf. Это не дополнительные условия приёмки 2690.

| Семейство | Сценарии | Проверки / основание |
|---|---:|---|
| DIFFERENT_CONDITIONS | 16 | ABC, разные conditionId, сценарий 1 стр.3-8 |
| SAME_CONDITION | 16 | ABC с одним conditionId, сценарий 2 стр.8-9 |
| MULTI_OBJECT_GROUPS | 16 | Несколько групп у двух объектов, разные параметры; §1.1 п.5c |
| ALTERNATIVE_MATRIX | 48 | 12 диапазонов, оба сервиса и оба allow; MAPPER таблица стр.16-31, REACTIONS-аналог |
| LAYERS | 8 | Document: 6 экспериментов, 3 слоя, оба allow; сценарий 3 стр.9-16 |
| FILTERED_ACTION | 4 | MAPPER actionType=2/4, оба allow; свежая спецификация стр.180-183 |
| KafkaReportContract | 8 | ABC/NONE, точный REST/Kafka состав и корреляция |
| LayerPriority / MultipleFinalExperiments | 9 | Ранее написанные REST-проверки выбора всех MAIN слоя |
| Всего | 125 | MAPPER 56 + REACTIONS 69 |

Document-матрица содержит 108 параметризованных строк. Проверяются точные objectId,
ruleCode, идентичности expId/expGroup/conditionId, число строк и дубли, salt, spreadValue,
layerId/priority, finalExpGroup, все groupResultParams и флаги. REST/Kafka и объекты
проверяются независимо через assertAll. Выбор MAPPER задан таблицей, не ответом текущей SDK.

requestDt необязателен; если присутствует, нужен Long epoch milliseconds и окно +/-5 минут.
resultDt обязателен в Kafka: положительный Long epoch microseconds и окно отправки/получения
REST +/-5 минут, включая последнюю миллисекунду. Автопересчёта единиц нет.
filtered для MAIN MAPPER обязателен при включённом filteredFlag: ожидаемая альтернатива
либо actionType=2/4 дают true, иначе false. Значение вычисляется из ожидаемой фикстуры.
no-MAIN допускает absent/null/[] или единственный строковый filtered=false.

Локально проверяются 108 синтетических наборов и 617 испорченных ответов.
Это подтверждает работу assertions, а не соответствие сервиса или всего PDF.
Произвольные профили, отключение фильтрации и return-suppressed=false не объявлены покрытыми.

Спорные требования сохранены без ослабления:
- Kafka ALL при allow=false: Тесты-v10 стр.7/15-16 требует сохранить связи;
  алгоритм свежей спецификации стр.96 переводит объект в несвязанные до формирования отчёта.
- MAIN[]: стр.96 допускает, стр.98 запрещает; ожидается отсутствие MAIN по согласованию.
- REACTIONS со слоями: стр.183-184 требует все MAIN выбранного приоритета.
  max-id=false не используется для оправдания выбора одного эксперимента.
- Без слоёв REACTIONS-аналог использует min-id и не создаёт альтернативу.
